# Spec citation

Quotes the **verbatim OMG UML 2.5.1 specification text**, with an exact clause number, when it has
been locally extracted. For questions about the metamodel's *structure* (features, generalizations)
rather than its prose, use `metamodel-lookup` instead - that data is always available (it comes
from the metamodel XMI, not the copyrighted PDF) and is usually a better answer to "what is a
Classifier"-style questions.

## Read order

1. `knowledge/installed.json` - resolve the default UML version.
2. `knowledge/<version>/spec/index.json` - if this file (or the whole `spec/` directory) doesn't
   exist, **spec text has not been extracted** - see "When spec text is missing" below and stop.
3. `knowledge/<version>/spec/index.json` is an array of `{clause, title, pages, normative, file}`
   rows. Find the clause covering the topic (search `title`, or use `metamodel-lookup`'s per-element
   markdown, which links each metaclass to its likely defining clause where known).
4. `knowledge/<version>/spec/clauses/<file>` - the clause's markdown, with YAML front matter
   (`clause`, `title`, `pages`, `normative`) and body text. Paragraphs wrapped in
   `<!-- informative:note -->`/`<!-- informative:example -->` comments are informative (NOTE/EXAMPLE
   blocks), not normative requirements - say so when quoting one.

## When spec text is missing

If `knowledge/<version>/spec/` doesn't exist (the PDFs haven't been fetched, or Python/the
`spec_extract` package isn't installed - see `tools/spec-extract/README.md`), **never fabricate a
quote**. Instead:
- If you can still name the likely governing clause (e.g. from a metamodel element's context or
  general UML knowledge), cite the clause **number only**, tagged **DERIVED**, and say plainly that
  this is a reference, not a verbatim quote.
- Tell the user how to unlock verbatim citation: run `uml4net-codex fetch --version <version>` (if
  not already fetched with PDFs) then `uml4net-codex generate --version <version>`.

## Known extraction limitations

`spec/` is generated by a best-effort PDF text-extraction pipeline (see
`tools/spec-extract/README.md`, "Known limitations"). Clauses whose page is dominated by a diagram
figure can have garbled body text; a bullet character can occasionally decode as a mojibake symbol.
If a clause's extracted text looks corrupted, say so rather than presenting it as a clean quote, and
suggest citing the clause number with a pointer to the official PDF page range instead.

## Answering

- Always state the clause number and the UML version.
- Tag a genuine verbatim quote as **NORMATIVE** only when `normative: true` in the clause's front
  matter; an informative NOTE/EXAMPLE excerpt is **NORMATIVE-adjacent but not itself a requirement**
  - say which it is.
- Keep quotes short and attributed; do not reproduce an entire long clause verbatim when a
  sentence or two answers the question.
